# Supabase Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace MongoDB with Supabase/Postgres as the `bbc` agent's store, preserving every DAO signature, all 158 tests, and on-chain trace-hash byte-identity.

**Architecture:** `agent/store/db.py` keeps all 50 public function signatures and return shapes; only its internals change, from `pymongo` to `supabase-py` (PostgREST over HTTPS, because a publishable key cannot open a Postgres connection). Schema ships as `agent/store/schema.sql`, run once by the operator in the Supabase SQL editor. Tests swap `mongomock` for an in-memory fake of the narrow PostgREST surface the DAO uses.

**Tech Stack:** Python 3.11+, `supabase-py`, pydantic-settings, pytest, Postgres 15 (Supabase), FastAPI, Next.js.

**Spec:** `docs/superpowers/specs/2026-09-09-supabase-migration-design.md`

## Global Constraints

- **Behaviour-preserving.** No change to agent behaviour, reasoning, GraphRAG, barbell strategy, treasury semantics, or Solana anchoring. The 158 existing tests must pass, changed ONLY where they assert Mongo-specific mechanics.
- **Every public function in `agent/store/db.py` keeps its exact signature and return shape.** Callers across `agent/`, `agent/api/`, and `agent/treasury/` must not change.
- **JSON columns are Postgres `text`, NEVER `jsonb`.** The DAO stores JSON as verbatim strings so on-chain trace hashes stay byte-identical; `jsonb` normalises key order and whitespace and would break `/verify/<id>` for every anchored trace. Affected: `markets.raw`, `decisions.search_used`, `decisions.response_json`, `market_snapshots.raw`, `graph_runs.ontology_json`, `graph_runs.stats_json`, trace-blob payloads.
- **Timestamps stay `text`** holding ISO-8601 UTC strings. `positions_today_pnl` prefix-matches on them.
- **Integer ids become `bigint generated by default as identity`.** The `counters` collection and `next_id()` are deleted.
- **The UNIQUE index on `flywheel_events.position_id` is load-bearing** — it is the flywheel's idempotency guarantee. So is the unique `(market_id, as_of)` on `market_snapshots`.
- Credentials: prefer `SUPABASE_SERVICE_ROLE_KEY` when set, else `SUPABASE_PUBLISHABLE_KEY`. The service role key must NEVER be exposed through a `NEXT_PUBLIC_*` variable.
- Import `settings` from `agent.config`, never `os.environ`.
- **LINTING:** never run `ruff format .` or any repo-wide format — this repo's committed style is not ruff-canonical and a repo-wide run produces hundreds of lines of churn. `ruff check` on touched paths; `ruff format` only on files you create. `mypy agent` must not exceed its 24 pre-existing errors.
- **Do not delete, drop, or overwrite any MongoDB data.** The existing local Mongo store holds the history behind the published traction numbers.

**Files:** Create `tests/fakes/postgrest.py`; Modify `tests/conftest.py`

- [ ] **Step 1: Enumerate the required surface.** Read `agent/store/db.py` and list every PostgREST call chain the rewrite will need. Write that list into the report before coding.

- [ ] **Step 4: Commit.** `test: in-memory postgrest fake replacing mongomock`

Then confirm a previously anchored trace still verifies at `/verify/<id>` — this is the proof that the `text`-not-`jsonb` choice preserved hash byte-identity.
